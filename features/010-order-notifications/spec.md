# 010 Order notifications: spec

- Status: verifying
- Created: 2026-11-16
- Target version: next release (UI + local settings only, no protocol/schema change)
- Owner: claude
- Links: [log](log.md) | [verify](verify.md) | [doc](doc.md)

## Goal
Tell the player about new orders they could craft (and news on their own orders) while the window is closed, with each
effect switchable in an options panel.

## Requirements
- R1: Someone else's new **open** order counts as new only when it is relevant to me: scope `profession` (default: I know the
  recipe, or I have the profession that holds it for any guild member), `known` (I know the recipe), `all`.
- R2: My own order counts as news when someone else claims it (a new claimer counts again) or marks it done (option `mine`).
- R3: The number of unseen items shows on the minimap button (red badge) and the Orders tab label (`Orders (n)`); the
  minimap icon becomes a letter while n > 0 (options `badge`, `icon`).
- R4: Opening the Orders tab marks everything as seen; the badge disappears. The first run of the feature does not treat
  the existing board as new.
- R5: For items that became new: chat line per item (max 3 + "and n more"), sound, screen message, taskbar flash; sound /
  screen / flash at most once per 10 s (a login sync brings many orders at once). Nothing is announced again at login for
  what was already unseen at logout (the badge still shows it).
- R6: Options panel in the game's AddOns settings (fallback: own window), opened via the window's **Options** button and
  `/ts options`; checkboxes for every effect, scope and sound choice with a Test button. Defaults: badge, icon, sound,
  chat, mine on; screen, flash off; scope profession.
- R7: Peer text (recipe name) never reaches chat or screen as markup.

## Non-goals
- Blizzard's mail indicator (`MiniMapMailFrame`) is not used: it belongs to real mail, the game shows/hides it on
  `UPDATE_PENDING_MAIL` and would override or confuse it. The letter icon is on TalentShare's own minimap button.
- No notifications for the Available tab (dibs).

## Design
- Files touched: `Core/Notify.lua` (new, pure: settings, relevance, unseen, seen, fresh); `UI/Alerts.lua` (new: controller,
  sound/chat/screen/flash, options panel, `/ts options`); `UI/Window.lua` (badge + letter icon on the minimap button,
  `UI.SetNotice`, `UI.OrdersVisible`, Options button, refreshOrders marks seen); `Locales/deDE.lua`; `TalentShare.toc`;
  `tests/run.lua` (loads Notify); `tests/test_notify.lua`.
- Data shape change: `db.ui.notify` (settings) and `db.ui.notifySeen[orderId] = stateKey` (own SavedVariables, pruned with
  the orders). Free-form `ui` table, read defensively (`Notify.Get`), no schema bump.
- Message shape change: none.
- Pure logic lives in: `Core/Notify.lua`; WoW calls (PlaySound, RaidNotice_AddMessage, FlashClientIcon, Settings) in `UI/Alerts.lua` under pcall.

## Review Focus (failure modes a happy-path test would miss)
1. RF1: login sync brings 20 orders -> one sound, chat capped at 3 lines + summary. Pinned by: Notify.THROTTLE, alert() cap (READ-ONLY).
2. RF2: peer recipe name with `|H` link markup -> plain `[Name]` in chat. Pinned by: `Model.ChatText` (009 test `whisper: a peer recipe name cannot inject a link`).
3. RF3: profession named in another language -> matched via skill line id. Pinned by: `notify: profession match works across languages`.
4. RF4: garbage in `notifySeen` / `notify` (hand-edited SavedVariables) -> defaults, no error. Pinned by: `notify: settings fall back...`, `notify: mark seen forgets pruned orders and ignores garbage`.
5. RF5: window open on the Orders tab when an order arrives -> marked seen immediately, no alert. Pinned by: `Alerts.Update` marks seen when `UI.OrdersVisible()` (READ-ONLY).

## Decisions (user answers and design choices, newest last)
- 2026-11-16: User asked to research options and add them as toggles; built directly (request was "add options"), assumption logged.
- 2026-11-16: No hijacking of the Blizzard mail icon (see Non-goals); letter icon + number badge on our own button instead ("if mail doesn't work show a number").
- 2026-11-16: "Relevant profession" = the recipe is held under a profession I have by any guild member in the store (skill line id), or I know it. Scope selectable.
- 2026-11-16: Default sound `IG_PLAYER_INVITE` (not `TELL_MESSAGE`, which players read as a whisper).
